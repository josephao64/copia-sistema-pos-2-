1. Resumen de la Funcionalidad

El módulo Multi-sucursal habilita al sistema para gestionar operaciones comerciales, inventarios, cajas y facturación de múltiples puntos de venta físicos o quioscos bajo una misma personería jurídica institucional.

2. Verificación de Criterios de Aceptación (Checklist)

CUMPLIDO 1. Todas las sucursales pertenecen a una única empresa.

Evidencia técnica:

  • src/SistemiPos.Domain/Organizations/Branch.cs: La entidad exige obligatoriamente la clave foránea CompanyId en el constructor. No existe sucursal sin empresa asociada.
  • src/SistemiPos.Infrastructure/Persistence/Configurations/BranchConfiguration.cs: Se define la relación relacional con Company con política OnDelete: ReferentialAction.Restrict.
  • src/SistemiPos.Application/Organizations/EnterpriseSettingsResolver.cs: Valida en cada operación que branch.CompanyId == companyId, bloqueando accesos cruzados.
CUMPLIDO 2. Una sucursal puede estar activa o inactiva.

Evidencia técnica:

  • Branch.cs contiene la propiedad bool IsActive y el método de dominio SetActive(bool isActive).
  • OrganizationService.ToggleBranchActiveAsync(id) y OrganizationController.ToggleBranchActive(id) permiten cambiar el estado operativo.
  • La interfaz administrativa (/Organization?tab=branches) muestra badges de estado y botones interactivos para activar/desactivar cada sede.
CUMPLIDO 3. Desactivar una sucursal no elimina su información histórica.

Evidencia técnica:

  • El sistema aplica borrado lógico (soft toggle). La sentencia DELETE sobre la tabla Branches está prohibida y bloqueada por el motor de base de datos.
  • Todas las tablas dependientes (Sales, CashSessions, InventoryMovements, Warehouses) conservan permanentemente su BranchId.
  • La base de datos cuenta con la restricción ReferentialAction.Restrict; si se intentase borrar físicamente, PostgreSQL rechaza la eliminación para proteger los datos históricos.
CUMPLIDO 4. El sistema debe identificar en qué sucursal se está operando.

Evidencia técnica:

  • Servicio central IOperationContextAccessor e implementación HttpOperationContextAccessor.cs que resuelven CurrentBranchId y CurrentBranchName en cada solicitud HTTP.
  • Almacenamiento seguro en la cookie .SistemiPosRestaurante.BranchContext.
  • La barra superior (_Layout.cshtml) muestra el selector desplegable cuando el usuario tiene múltiples sucursales, o el badge de sucursal fija cuando tiene una sola.
  • Los módulos de inventario, cajas y ventas filtran automáticamente sus datos según CurrentBranchId.
CUMPLIDO 5. Un usuario puede tener acceso a una o varias sucursales.

Evidencia técnica:

  • Entidad relacional UserScopeAssignment con nivel de alcance UserScopeLevel.Branch.
  • Permite asociar una colección de sucursales autorizadas (SelectedBranchIds) y una sucursal de entrada por defecto (DefaultBranchId).
  • Formulario de administración de usuarios (Users/Form.cshtml y UsersController.cs) permite seleccionar las casillas de sucursales permitidas para cada empleado.
  • Seguridad estricta: Si un usuario intenta acceder a una sucursal no asignada, el sistema rechaza la petición con UnauthorizedAccessException.
